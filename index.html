我们希望用大模型做 OPC 的迭代优化。现在的认识主要来自 VPEvolve 及实验适配，还缺少真实工厂任务的参照，想先把工作流理解清楚。

WORKSPACE环境与文件工程师拿到什么？
TOOLS工具与动作能运行、能修改什么？
TASK具体任务这次要解决什么？
ITERATION执行与反馈如何观察、再调整？
ACCEPTANCE验收与交付怎样判断做完了？
当前实验

GDS / 局部窗口 → 初始 recipe + 固定研究工艺模型 → Calibre → 指标反馈 → 再修改。
希望请您指出：这条流程与工业实践的关键差异在哪里？

01 / 环境与任务包

一次真实任务，
工程师会拿到什么？

类比 coding：开始工作之前，workspace 里有哪些东西？

A

版图的范围有多大？

是整个芯片的 GDS、指定图层，还是一组代表性局部图形？局部窗口由谁选，周围的邻近图形如何保留？

B

除了版图，还会附带什么？

初始 recipe、工艺模型、目标图形、工具及版本、已有热点和验收标准，哪些通常已准备好？

C

哪些固定，哪些需要开发？

工艺模型由哪个团队建立和校准？OPC 工程师的任务边界在哪里，哪些参数或文件允许调整？

想确认：一个可执行的工业 OPC 任务包，最少包含哪些文件与约定。

02 / 工具与权限边界

工程师能改什么，
又通过什么工具完成？

类比 coding：模型需要知道可用的命令、可编辑的文件，以及执行后的反馈。

A

主要操作是改 recipe，还是直接改局部几何？

调参数、写图形相关规则、移动边缘、调整 SRAF，这些动作分别在什么场景下使用？

B

实际使用哪些工具与资料？

如果使用 Calibre，通常用哪些产品或模块？哪些操作走命令行或脚本，哪些依赖 GUI？遇到问题会查哪些手册或内部经验？

C

一次运行能返回哪些诊断信息？

只有汇总分数，还是能拿到轮廓、误差位置、违规类型、日志和可视化？工程师怎样据此决定下一步？

想确认：Agent 应获得怎样的工具接口、操作空间和观察结果。

03 / 优化与迭代

局部调好以后，
如何覆盖整个图层？

我们目前主要在局部窗口里反复修改、仿真、比较结果。

A

开发 recipe 的典型流程是什么？

先在测试图形或热点上调好，再推广到全图层；还是直接跑全图层，再挑出问题迭代？

B

一次局部修正，作用范围是什么？

只修某一个坐标位置，还是提炼成适用于所有相似图形的规则？这些规则怎样匹配、如何处理相互冲突？

C

工程师通常怎样安排实验？

先解决哪类问题？何时做局部验证、全图层验证或回退？迭代次数、算力和人工判断各占什么位置？

想确认：一次真实的“观察 → 修改 → 运行 → 再判断”是怎样发生的。

04 / 改善能否推广

怎样避免“修好这里，
弄坏那里”？

局部指标变好，是否足以说明 recipe 真正变好了？

A

用什么回归集验证一条新规则？

测试图形、历史热点、代表性设计和全芯片检查分别在何时使用？怎样选取足够有代表性的样本？

B

局部窗口的结论，怎样确认可靠？

裁剪边界、周围图形和版图密度会带来哪些影响？需要多大范围的上下文，怎样验证边界没有改变结论？

C

局部收益与全局退化，怎样取舍？

如果最坏点改善，但其他位置或其他工艺条件变差，什么情况可以接受，什么情况必须回退？

想确认：工业上的回归覆盖、推广门槛和保留新版本的依据。

05 / 判断任务完成

什么结果，
才算真正合格？

希望区分必须满足的硬约束、用于比较优劣的指标，以及最终确认方式。

想确认的维度请教的问题
图形保真EPE、CD 等指标怎样设阈值？最坏点、违规数量和整体统计，分别怎样影响验收？
工艺鲁棒性怎样考核工艺窗口、焦距 / 剂量变化、PVB？哪些工艺条件必须覆盖？
可制造与成本掩模制造规则、SRAF 意外打印、运行时间和掩模复杂度，哪些是一票否决，哪些可以权衡？

仿真通过后，还需要怎样的实际测量确认？模型误差、晶圆测量与仿真不一致时，怎样定位责任和调整流程？

想确认：可机器执行的验收标准，以及仿真合格与生产合格的关系。

06 / 输出与工作重心

最后交付什么，
精力主要花在哪里？

我们想找出值得交给 Agent 的具体环节，而不只是在 benchmark 上调分数。

A

交付物到底是什么？

优化后的掩模版图、可复用 recipe、工艺参数、验证报告和运行记录，分别由谁交付、谁验收？

B

最费时间和经验的是哪一步？

定位问题、理解成因、调参数、写局部规则、等待仿真、回归验证，还是跨团队确认？能否举一个近期的典型例子？

C

我们的 benchmark 最遗漏什么？

如果只能补上一个工业难点，您会选什么？哪些步骤适合先自动化，哪些判断仍需工程师负责？

想确认：真正有价值的任务边界，以及评价 Agent 是否有帮助的方法。

07 / 最后用一个例子串起来

能否用一个脱敏任务，
带我们走一遍？

不必先提供实际数据；先口述一个任务的结构，也能帮助我们建立正确理解。

任务起点
谁提出了什么问题？最初有哪些文件、已有结果和固定条件？
可用动作
工程师会打开哪些工具、查什么资料，允许修改哪些内容？
一次迭代
看到什么现象 → 做出什么修改 → 跑什么检查 → 怎样决定保留或回退？
完成条件
满足哪些阈值、完成哪些回归、由谁确认，最后交付什么？

希望带走：最小任务包 + 基线工作流 + 验收方式。据此再设计一个贴近真实工作的 OPC Agent 试点。
